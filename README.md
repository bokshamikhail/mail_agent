# Summary Agent

Интеллектуальный агент для автоматической обработки входящей корпоративной почты. Проект решает две основные задачи: **классификацию писем** по категориям и **генерацию кратких сводок** по содержанию сообщений. Решение ориентировано на сокращение времени ручной обработки почты и упрощение маршрутизации входящих обращений.

## Возможности

- классификация входящих писем по заданным классам;
- генерация краткого саммари для каждого письма;
- пакетная обработка набора писем;
- запуск inference на подготовленных данных;
- расширяемая архитектура для подключения новых моделей и правил постобработки.

## Где может применяться

Проект подходит для сценариев, где необходимо быстро обрабатывать большой поток корпоративной почты:

- служебные и внутренние обращения;
- заявки и запросы пользователей;
- сортировка писем по типам;
- предварительный анализ входящих сообщений перед передачей сотруднику.

## Стек

В проекте используются инструменты для NLP-обработки текстов и построения пайплайна обработки писем:

- **Python** — основной язык разработки;
- **pandas / numpy** — обработка данных;
- **scikit-learn** — базовые инструменты машинного обучения и оценки;
- **FastText** — получение эмбеддингов;
- **CatBoost** — классификация;
- **LLM API / генеративная модель** — создание кратких сводок по письмам.

> Точный список зависимостей и версии библиотек рекомендуется смотреть в `requirements.txt` или в конфигурации окружения проекта.

## Архитектура решения

Общий пайплайн работы выглядит так:

1. загрузка входных писем;
2. предобработка текста;
3. классификация письма;
4. генерация краткого саммари;
5. сохранение результата в удобном формате.

На выходе для каждого письма формируется:

- исходный текст или идентификатор письма;
- предсказанный класс;
- краткая сводка содержания.

## Формат входных данных

Обычно на вход подаются письма или таблица с письмами, содержащая как минимум одно текстовое поле, например:

- `subject` — тема письма;
- `body` — текст письма;
- `label` — класс письма, если данные используются для обучения.

Пример табличного формата:

| id | subject | body | label |
|----|---------|------|-------|
| 1 | Request for access | Please grant access to... | access |
| 2 | Meeting rescheduled | The meeting has been moved... | info |

## Формат выходных данных

После обработки для каждого письма могут сохраняться:

- предсказанный класс;
- вероятность или score модели;
- краткое саммари;
- дополнительные служебные поля.

Пример результата:

| id | predicted_label | summary |
|----|------------------|---------|
| 1 | access | Запрос на предоставление доступа к системе. |
| 2 | info | Уведомление о переносе встречи на другое время. |

## Обучение моделей

В проекте могут использоваться разные подходы к классификации:

### FastText

Подходит для быстрого базового решения, когда важны скорость обучения и простота применения.

### BERT-подобные модели

Подходят для более точной классификации, особенно если письма различаются по смыслу и формулировкам.

### Генерация саммари

Для суммаризации может использоваться внешняя LLM через API либо локально доступная генеративная модель. Саммари строится отдельно для каждого письма.

## Пример сценария использования

1. загрузить набор входящих писем;
2. запустить скрипт обработки;
3. получить для каждого письма класс и краткую сводку;
4. использовать результат для сортировки, приоритизации или передачи ответственному сотруднику.

## Метрики качества

Для оценки качества классификации обычно используются:

- экспертная оценка полезности;

- автоматические метрики при наличии эталонных саммари.
